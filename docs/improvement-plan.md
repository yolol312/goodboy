# goodboy 발전 계획 — 가드레일 정체성 확정

> 2026-07-30 수립. 결정: goodboy는 워크플로우 프레임워크가 아니라 **모든 워크플로우 위에 얹히는
> 품질 보증 가드레일 레이어**로 발전한다. MoAI-ADK·gstack 벤치마킹과 3주간의 실사용
> 오탐 수정 이력(v0.26.3~v0.27.9)에서 도출했다.

---

## 1. 목적 선언

- **정체성**: 어떤 개발 워크플로우(수제 스킬, MoAI-ADK, gstack, 순정 Claude Code) 위에도
  얹혀서, 모델이 스스로 지키지 못하는 품질·안전·비용 규율을 **강제력 있게** 보증한다.
- **차별 자원**: 결정적 차단 게이트 + 탈출구. 대형 하네스들의 게이트 다수는 advisory이고,
  강제력 있는 경량 레이어 자리는 비어 있다(MoAI-ADK 소스 대조로 확인).
- **하지 않는 것**: 개발 방법론 소유(SPEC 라이프사이클), 모델·비용 라우팅, 자율 루프,
  대형 스택화. 프레임워크의 좋은 요소는 **산출물 검증 게이트** 형태로만 흡수한다.

## 2. 게이트 설계 원칙 v1 — 판단 기준의 명문화

3주간의 오탐 수정 이력에서 귀납한 규범. **신규 게이트와 기존 게이트 개정은 모두 이 기준으로
심사한다** (리뷰 에이전트 체크리스트에 편입).

### 2.1 개입 강도 결정 매트릭스

개입 강도는 "손상의 비가역성 × 판정의 확실성"으로 정한다.

| | 판정이 **결정적** (로컬 사실로 확인 가능) | 판정이 **확률적** (추정·휴리스틱) |
|---|---|---|
| **손상 비가역/큼** | `deny` 차단 (탈출구 필수) | `ask` — 사용자 승인 마커로 위임 |
| **손상 가역/작음** | `warn` 비차단 경고 | `advisory` — 세션·패턴당 1회 정보 |

- 사례: Read-before-edit(기록=사실 → deny), 웹 재페치(페이지가 바뀌었을 수 있음=확률적 → warn),
  위험 작업(정당한 사용 사례 존재 → ask 승인 마커), 토큰 습관(advisory).
- **추측 기반 차단 금지**: 컨텍스트 한도 미확정 시 강제 compact를 보류하는 3-A 결정이 선례.
  확신 없는 판정으로 deny하지 않는다.

### 2.2 게이트 불변 규칙 (전 게이트 공통)

1. **fail-open** — 판정 실패·파싱 불가·내부 오류는 통과. 가드레일 고장이 작업을 멈추면 안 된다.
2. **탈출구 필수** — 모든 deny는 escape(N회)·env·승인 마커 중 최소 하나의 출구를 갖는다.
   "탈출구 없는 게이트 금지"(D 원칙).
3. **자기 교정적 메시지** — deny/warn 메시지는 규칙 자체와 해소 방법을 담아, 처음 만나는
   에이전트(다른 하네스의 서브에이전트 포함)도 메시지만으로 순응할 수 있게 한다.
4. **상태 스코프 분리** — 게이트 상태는 `agent_id ?? 'main'`으로 키잉한다. 메인·서브 교차
   간섭 금지(v0.26.4 사고 재발 방지).
5. **채널 규율** — 에이전트에게 도달해야 하는 경고는 도달이 실측 확인된 채널만 쓴다
   (PostToolUse `additionalContext`, deny reason). PreToolUse 사전 경고는 에이전트에 닿지
   않는다(실측) — 금지.
6. **시간·창 정렬** — "컨텍스트 수명" 근사치(현행 30턴)는 단일 상수로 공유한다. 게이트끼리
   창이 어긋나면 한쪽이 다른 쪽의 낭비를 유발한다(RBE 20턴 vs 재Read 30턴 사고).
7. **하니스 비동기성 전제** — transcript 기록은 지연된다(실측 19~40초+). transcript 기반
   판정은 지연 확정(lag-confirm)·플러시 대기·경계 마커 인식 같은 지연 내성 설계를 갖춘다.

### 2.3 품질 게이트 SLO (마찰 예산)

- **오탐 예산**: 게이트당 세션당 헛 차단 ≤ 1회. 초과가 관측되면(gate-log) 그 게이트는
  버그로 취급한다 — v0.27.4/0.27.7(추론 게이트), v0.27.6(compact 게이트)이 이 기준의 적용례.
- **지연 예산**: 차단 판정은 5초 이내. 대기(플러시 폴링 등)는 명시적 opt-out env와
  훅 타임아웃 15초 여유를 갖춘다.
- **검증 기준**: 신규·개정 게이트는 (a) 회귀 테스트, (b) **변이 사살 테스트**(핵심 분기를
  제거한 변이가 테스트에 죽는지 실증), (c) 필요시 라이브 검증(/verify — 모델이 유도대로
  움직이는지)을 통과해야 병합한다.
- **관측 가능성**: 모든 발동을 gate-log(jsonl)에 기록. "발동 0회 게이트"는 커버리지 구멍
  신호로 정기 점검한다(tokenhabit H2-01 ×334 vs reread 발동 0회 사례).

### 2.4 판정 신호 등급제 (2026-07-30 추가)

훅 판정의 명확성·일관성을 위해, 모든 게이트의 근거 신호를 등급화하고 **등급이 개입 강도의
상한을 정한다**. 근거: 3주간의 오탐은 전부 "추정 신호에 사실 신호의 강도(deny)를 부여"한
지점에서 발생했다.

| 등급 | 신호 | 허용 강도 |
|---|---|---|
| **T0 사실** | hook 입력, 파일시스템(존재·mtime), 자체 기록(reads/edits.jsonl, exit code) | deny 가능 |
| **T1 신뢰 프록시** | transcript 구조 필드(usage·모델·경계 마커) — 내용은 정확하나 기록이 지연 | deny 가능하되 **지연 내성 설계 의무**(lag-confirm·플러시 대기·경계 인식) |
| **T2 추정** | 한도 추론, 텍스트 파싱(추론 섹션 인식), 패턴 휴리스틱 | 원칙 warn/ask. deny하려면 보정 장치(escape·confident 보류) 의무 |

- 운영 규칙: (a) 기존 게이트 전수 감사로 등급-강도 불일치 목록화, (b) **임계값 레지스트리**
  — 모든 상수(30턴·50%·25%·8엔트리·escape 3회·20초·3일)를 `{값, 근거(실측/관례), 소속
  게이트, 마지막 검토일}`로 단일 문서화(§4-1 env 레지스트리와 통합), 근거가 "관례"인 임계는
  텔레메트리(2-2) 검증 대상으로 자동 지정, (c) **무력화 감지** — 게이트별 판정 불가율을
  gate-log에 기록, 발동 0회 지속·파싱 실패 누적 시 상태바 표시(`N%?`의 일반화), 실제
  transcript 샘플 고정 계약 테스트로 하니스 포맷 변경을 조기 감지, (d) 텍스트 파싱이
  불가피한 곳은 인식 문법(허용 변형)을 명세+테스트로 고정하고 거짓 양성(게이트 메시지
  재인용 오인식 등)을 정례 감사.

### 2.5 판정 방법론 — 무엇을·언제·어떻게 판정할 것인가 (2026-07-30 추가)

> "행동은 사실로, 품질은 사후에, 강제는 합의로"

1. **판정 대상: 주장 → 행동·산출물.** 텍스트 파싱(T2)보다 검증 가능한 행동 흔적(도구 호출
   기록, exit code, 산출물)을 근거로 삼는다. 증거 게이트(1-1)가 첫 적용.
2. **판정 시점: 사전 유도, 사후 확정.** 정보가 불완전한 시점(PreToolUse — 현재 턴 텍스트
   부재)에는 확정 판정하지 않는다. 사전 게이트는 넛지(경고·1회)로, 확정 판정·강제는 정보가
   완전한 Stop(플러시 완료·전체 턴 관측)으로 옮긴다. 손상이 **비가역**인 것(위험 명령·자격
   증명 — T0로 판정 가능한 영역)만 사전 deny가 정당하다. → **추론 게이트 재설계(Phase 2
   신규 2-4)**: PreToolUse는 1회 넛지로 강등, Stop에서 "턴 내 편집 ↔ 추론 섹션 대응"을
   확정 검사(그 시점엔 지연 소멸 = 사실상 T1) + 품질은 리뷰 차원(3.5.1). 지연 오탐과의
   싸움을 장치 추가가 아니라 구조로 종결한다. 3주 개선 궤적(deny → sticky 경고+리뷰 수렴)이
   이미 이 방향이었음을 명문화.
3. **강제는 독립 신호 2개의 합의로.** compact 강제(usage% + 한도 confident), RBE(기록 +
   mtime)가 선례. 단일 신호 deny를 신설하지 않는다.
4. **개별 행위 판정 → 세션 예산 판정.** "이 Read가 재독인가"(개별, 오탐 민감)보다 "이 세션
   재독이 예산 N회를 넘었는가"(총량, 오탐 무해화)가 강건하다. 재독·재페치 게이트의 예산형
   전환을 검토(컨텍스트 게이트가 총량형이라 안정적인 것과 같은 원리).
5. **판정 불가는 판정하지 않되, 불가율을 관측한다.** fail-open 유지 + 2.4(c) 무력화 감지.

## 3.5 리뷰 체계 개편 (2026-07-30 추가 — 사용자 요구)

현행 리뷰는 단일 에이전트(review-changes)가 차원 목록(dimensions_checked)을 자율 선택한다.
이를 **차원 카탈로그 + 상시 차원 + 오답노트 순환**으로 개편한다.

### 3.5.1 리뷰 차원 카탈로그

| 차원 | 내용 | 발동 조건 |
|---|---|---|
| 기능 정확성 | 요구사항 충족, 엣지 케이스, 회귀 | 상시(코드 변경 시) |
| 보안 | 입력 검증, 자격증명 노출, 인젝션, 위험 명령 | 상시(코드 변경 시) |
| **환경(신설, 상시)** | 이번 작업에 사용된 환경 — 프레임워크·버전·도구·API의 버전 특이사항, deprecated 사용, 환경 기인 함정 | **상시** — 결과가 오답노트의 원천 |
| 추론 품질(신설) | `## 추론` 섹션의 사실에 근거가 있는가, 가정이 검증 가능한 형태인가, 추측이 사실로 승격되지 않았는가 | 상시(추론 섹션 존재 시) |
| 성능 | 복잡도, 불필요 연산, 리소스 누수 | 코드 파일 변경 시(현행 requiredDimensionsFor 확장) |
| 테스트 실효성 | 커버리지가 아니라 **변이 관점**(테스트가 구현을 실제로 구속하는가) | 테스트 변경/신설 시 |
| 컨벤션 | 프로젝트 규칙·스타일 정합 | 상시(경량) |

- Stop 게이트의 F2(필수 차원 검사)를 이 카탈로그 기준으로 확장 — "가능한 필요한 리뷰는
  다 한다"를 게이트가 보증한다.
- 게이트 설계 매트릭스와 일관: 차원 누락은 **결정적 판정**(목록 대조)이라 수락 보류 사유,
  차원 내부의 품질 판단은 **확률적**이라 리뷰 에이전트(LLM)의 몫.

### 3.5.2 오답노트(환경 회고 원장)

- **저장**: 환경 리뷰 결과 중 "조심할 점 / 개선 방향"을 프로젝트 원장
  `.claude/goodboy-retro.jsonl`에 적재. 각 항목은
  `{환경 지문(프레임워크+버전 등), 주의사항, 개선 지침, 출처 리뷰, ts}`.
- **주입**: 세션 시작(핸드오프 주입 1-3과 동일 채널)에 현재 환경 지문과 매칭되는 항목만
  요약 주입 — "이 프로젝트의 이 환경에서는 X를 조심하라".
- **자동 만료(자가 치유 지식)**: (a) 환경 지문 변화 감지(lockfile·설정 파일의 프레임워크
  버전업, 새 프레임워크 도입/병행) 시 옛 지문 항목 삭제, (b) 보존 기간(기본 90일) 경과
  항목 삭제. 삭제 근거: **재발하면 환경 리뷰가 다시 적재한다** — 리뷰 파일 자동 위생
  (v0.27.5)과 같은 철학. 오답노트는 낡은 지식을 쌓는 곳이 아니라 현재 환경의 활성 주의보다.

### 3.5.3 서브에이전트 역할 로스터 (역할 문서화)

- **판단: 채택.** 오케스트라·팀 에이전트(상주 다중 에이전트 + 조정 라운드)와 달리, 역할
  문서화는 **이미 호출하는 단발 서브에이전트의 프롬프트를 표준화**하는 것이라 추가 비용이
  거의 없고(역할 정의는 호출 시에만 로드), 매 호출마다 역할·기준·출력 형식을 즉석에서
  다시 쓰는 현행 방식보다 오히려 토큰을 절약한다. Claude Code의 `agents/*.md` 정의가
  정확히 이 용도이며 goodboy:review-changes가 이미 선례다.
- **로스터(소수 고정)**: reviewer-security / reviewer-environment / reviewer-reasoning /
  planner(계획 검토) 등 차원별 역할 정의 파일. 단발 호출·직렬 사용이 원칙 — 상주 팀·
  브로드캐스트 금지(그게 오케스트라의 토큰 폭발 지점).
- **비용 가드**: 차원별 에이전트를 병렬 남발하지 않도록, 기본은 **단일 리뷰 에이전트가
  카탈로그 차원을 순회**하고, 위험도 높음·대형 변경에서만 차원 분리 호출(2~3개 상한).

## 3.6 입력·추론 품질 개선 (2026-07-30 추가 — 사용자 요구)

- **프롬프트 검사(B2) v2**: 현행 고정 체크리스트 주입 → 작업 카테고리 인지형(버그=재현·현재
  동작, 기능=수용 기준, 리팩토링=동작 동일성 범위)으로 점검 항목을 특화. "확인 필요" 선택
  항목이 `## 추론 > 가정`에 실제로 기록됐는지 Stop의 F1.5 연동을 카테고리별로 강화.
- **추론 게이트 품질**: 게이트 자체는 구조 검사(4분류·비어있음)를 유지한다 — 내용 판단은
  확률적이므로 차단 사유가 될 수 없다(매트릭스 원칙). 내용 품질은 3.5.1의 "추론 품질" 리뷰
  차원이 담당: 사실의 근거, 가정의 검증 가능성, 추측→사실 승격 여부를 채점하고 finding으로
  반환 → 오답노트와 동일한 순환으로 학습된다.

## 4. 기존 기능 품질 향상 (설정·운영)

1. **env 스키마 정리** — `GOODBOY_*` 30여 개를 단일 레지스트리(이름·타입·기본값·소속 게이트)로
   선언하고 README 표를 자동 생성. 미등록 `GOODBOY_*` env 감지 시 오타 경고(무시된 설정은
   침묵 실패가 아니라 신호여야 한다).
2. **프로파일 프리셋** — `GOODBOY_PROFILE=strict|standard|light`. light=경고 중심(도입기),
   standard=현행, strict=escape 축소·advisory 승격. 개별 env가 프로파일을 덮어쓴다.
3. **gate-log 표준 스키마** — `{ts, gate, decision, reason, scope}` 통일 + 세션 종료 시
   요약 1줄(발동/차단/escape 수). 2-2 텔레메트리의 기반.
4. **라이브 검증 정례화** — /verify 레시피를 릴리스 전 체크리스트로 승격(단위 테스트는 훅
   로직만 검증 — 모델 유도 효과는 라이브로만 확인된다는 원칙 유지).
5. **문서 이원화** — README(사용자용)와 별개로 `docs/gate-design.md`(이 문서 2장의 원칙 +
   게이트별 판정 근거·탈출구·SLO 표)를 유지해 설계 판단 기준을 코드 리뷰 기준으로 쓴다.

## 6. 성공 지표

- **tokenhabit 점수**: B(낭비 10%) → A(5% 이하). 특히 H1 계열(오탐 수정 반영)과 H2-01 감소.

  워밍업 3회 이내로 안정화되는지.
