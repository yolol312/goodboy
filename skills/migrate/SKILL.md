# 마이그레이션

스키마, 데이터, 인프라처럼 되돌리기 어려운 변경을 수행하는 워크플로우입니다. 기본 위험도가 **위험(risky)** 이며 사용자 승인 마커가 없으면 편집이 차단됩니다.

## 워크플로우

1. **필수 정보 수집**: UserPromptSubmit hook이 누락 정보를 자동 감지합니다. 누락이 있으면 `AskUserQuestion`으로 묶어서 묻고, 각 질문에 "확인 필요" 옵션을 자동 포함시킵니다.

2. **추론 가시화** ⚠️ 필수: 작업 시작 전에 다음 형식으로 `## 추론` 섹션을 출력하세요. 이게 없으면 PreToolUse hook이 편집을 차단합니다.

   ```markdown
   ## 추론

   ### 사실 (검증됨)
   - 실제 Read한 코드/문서로 확인된 것만 (롤백 절차, 백업 위치 포함)

   ### 추론 (사실에서 도출)
   - 검증 가능한 논리적 추론

   ### 가정 (정보 부족)
   - 사용자가 "확인 필요"라 답한 항목들 — 어떻게 가정하고 진행할지

   ### 추측 ⚠️ (근거 약함)
   - 검증 없이 채운 부분. 리뷰가 우선 검증함
   ```

3. **카테고리별 세부 단계** — 아래 섹션 참조.

4. **자동 검증**: Edit/Write 후 PostToolUse hook이 타입체크/린트/테스트 자동 실행. 실패 결과는 컨텍스트로 주입되니 확인 후 수정.

5. **리뷰** ⚠️ 필수: 작업 완료 직전에 `review-changes` 서브에이전트를 호출하세요. Stop hook이 리뷰 결과 파일이 없으면 종료를 차단합니다.

   ```
   Agent(general-purpose, "review-changes 스킬에 따라 다음 파일을 리뷰: <변경 파일>")
   ```

   또는 review-changes 슬래시 커맨드/스킬 호출. 마이그레이션은 깊은 리뷰가 필요하므로 롤백 가능성과 데이터 손실 검사를 명시적으로 요청하세요.

## 카테고리별 세부 단계

1. ⚠️ **위험도 위험**: 편집 전에 사용자 승인 마커(`.claude/.goodboy-risk-approved.txt`) 존재 여부를 확인하세요. 없으면 다음과 같이 사용자에게 명시적 진행 승인을 요청하고, 사용자가 승인하면 본인이 직접 마커 파일을 만들도록 안내하세요:

   ```
   이 작업은 위험(risky) 카테고리입니다. 다음 절차를 확인하고 승인해 주세요:
   - 롤백 계획: ...
   - 검증 환경: ...
   - 위험 데이터/스키마: ...
   - 허용 다운타임: ...

   진행 승인하시면 `.claude/.goodboy-risk-approved.txt` 파일을 생성해 주세요.
   ```

2. 롤백 계획을 `## 추론 > 사실`에 명시 (말로만 적지 말고 구체 명령/SQL/스냅샷 ID 수준)
3. 검증 환경에서 dry-run 우선 (staging/local/canary 중 사용자가 답한 곳에서)
4. 데이터 백업 확인 (스냅샷/덤프 존재 + 접근 가능 + 복원 절차 검증)
5. 마이그레이션 실행 + 검증 (변경 직후 핵심 쿼리/헬스 체크)
6. 깊은 리뷰 호출 (서브에이전트가 롤백 가능성, 데이터 손실, 다운타임 예상치를 점검)

## 설계 시 반영할 품질 차원 (해당 시)

⚠️ **shift-left**: 전체 체크리스트는 `/add-feature`의 "설계 시 반영할 품질 차원" 섹션 참조. migrate에서 특히 챙길 것:

- **에러 경로 & 데이터 안전(`error-path` / data-safety)**: malformed·부분·손상된 입력 데이터를 만나도 fail-closed(조용히 빈 값으로 폴백한 뒤 덮어써 원본을 날리지 말 것 — 이건 리뷰에서 `high`). 비원자적 쓰기(temp+rename 아님) 금지.
- **롤백(rollback)**: 롤백 경로를 코드로 함께 작성하고, 적용→롤백을 실제로 한 번 돌려 원상 복구·데이터 손실 없음을 확인(리뷰의 롤백 프로브가 이걸 재현함).
- **성능(`performance`)**: 대량 데이터 경로에서 행 단위 동기 IO·O(n) 전체 재작성이 다운타임을 늘리지 않는지 확인. 트레이드오프는 `## 추론`에 명시.

## 위험도

이 카테고리의 기본 위험도: **위험(risky)**

- 단순(simple): 자동 진행 게이트 — 추론 가시화만 필수
- 중간(medium): 추측 카테고리에 항목이 있으면 사용자 확인 게이트
- 위험(risky): 항상 사용자 승인 마커(`.claude/.goodboy-risk-approved.txt`)가 있어야 편집 가능. 사용자에게 "진행 승인" 명시 요청.

`--risk <level>` 인자로 override 가능. 예: `/migrate --risk medium <설명>` (단, 마이그레이션의 위험도를 낮춰 부르는 일은 신중히)

## 주의사항

- "확인 필요" 답변은 정당한 입력입니다. 모델이 거짓 답변하지 말고 그대로 가정 단계에서 명시하세요.
- `## 추론 > 가정` 섹션에 "사용자가 X에 대해 모른다 → ~로 가정"이라고 명시.
- 추측이 많을수록 리뷰가 엄격해집니다. 가능하면 사실/추론 비중을 높이세요(Read로 검증).
- 롤백 계획이 "확인 필요" 또는 추측에 머문다면 마이그레이션을 진행하지 말고 사용자에게 재확인하세요.
- 본 워크플로우는 변경을 적용까지 가져가지 않고 마이그레이션 스크립트/계획 작성 + dry-run까지로 끊는 것이 안전합니다. 실제 프로덕션 적용은 사람이 트리거.
